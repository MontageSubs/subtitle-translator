## 1. 产品与价值观(任何文案不得违背)

- **定位**:免费、无账号的字幕翻译与整理工作台,是社区的"基层公共服务与入口",**不是商业产品**。刻意**不做 API**(API 无法让人认识并加入社区)。
- **战略角色**:把"看片的人"变成"做字幕的人",再变成"社区成员"。
- **工作方式**:合并成完整句子 → 打包成场景 → 去掉时间轴和符号,以"文档"形式交给 NMT → 译文精确回填原时间轴。另有校对预览、格式互转、SDH 去除等。
- **价值观清单**:免费且不因支付能力区别对待;无账号、无广告、不追踪、不用 cookie、不保留字幕内容(历史只在浏览器本地);防滥用但尊重隐私;开源 MIT 与可验证的透明;**诚实面对局限**(关于页写明"200 多种语言不代表每一对质量都完美")。
- **三层支柱**:本工具(快,尽量好);LLM 翻译体系(内部成员用,**不对外提**);人工翻译(产量低)。"披露机器参与程度"只针对字幕组项目,不适用于翻译器。
- **术语统一**:翻译模型一律叫**"翻译引擎"**(en: translation engine;pl: silnik tłumaczenia;de: Übersetzungs-Engine)。models 页必须与翻译界面一致。

## 2. 用户(项目负责人)的工作偏好

1. **要我独立判断**:选最佳方案并说明理由,别反复问;一次最多问一个问题。
2. **项目守护者**:需求破坏性能/优雅/项目本意时,拒绝并给专业理由;复杂编码前先说意图理解,但用户说"开始"就直接做。
3. **两条线**:机器可读元数据(我负责,可广撒网但必须真实);**用户可见内容**(H1/正文/按钮/导航)按社区风格:自然、克制、专业、少营销。
4. **回复风格**:直接、不客套、重要内容用表格;简单问题 300 字内;复杂可展开;用户要"完整回复"时逐条回答。
5. **交付格式**(每次都用):① 改动清单 ② 目标达成 ③ 方案修正(被拒绝/优化的需求及理由)④ 删除文件 ⑤ 需用户确认/知道的事(未验证项、会影响可见内容的改动)。
6. **并行开发**:用户随时改 UI/i18n。**每个对话开始先 clone 最新 `main`**(新克隆要 `git fetch --depth=3000` + `npm ci`),有冲突智能合并;用户删/改了 key 或译文必须跟上;新增功能先理解意图再翻。
7. **行级最小改动**:Python 逐行编辑 JSON,键保持字典序,**绝不整体重排**(插入时只在目标行后加一行;重排会污染 es/hu 等并行语言的 diff)。
8. **环境习惯**:命令不在前台阻塞(不用长 `sleep`,构建放后台);**不用无头浏览器做视觉检查**(算法/数学上保证正确,视觉用户看);联网仅限项目 GitHub、必要资源和信息核实(但**调研类联网用户已明确授权不限制**)。
9. **代码里不写注释**;删除要清死代码。
10. **已有/非我负责的语言(es、hu、he、fa)不要碰**;发现我自己的旧语言有问题要负责修。对英语/现有 i18n 的问题:**只建议,不直接改**(除非用户明确要求,如"引擎"措辞)。
11. 报告/共识/决策**禁止进仓库**(仓库面向公众)。文档只维护**本文这一份**(Projects 工具里的 `claude/i18n-handoff-portable.md`)。
12. **RTL 体系用户在做**(he/fa 同步优化中):我只做无需 RTL 的部分,不要动 RTL 相关代码与语言。
13. **本地任务不涉及 python 翻译逻辑和 worker 后端侧改动,无需同步。**
14. **凡是与用户协商/批准过的改动,必须当轮做完**,不得以"会触发全员更新""等下次再说"为由推迟(例:`credit.text`、`context.willTranslate` 的英文结构已改)。
15. 用户本地没有 `/home/claude/exp`,以后不必再提。

## 3. 翻译的"意图"(最重要)

> 用户原话要点:**情感上等价,而非文字上等价**。目标是任何语言的用户打开工具都觉得"这个工具非常棒,是我们语言中的佼佼者",而不是"外来工具,与我的文化格格不入"。禁止翻译腔、机翻感。

- **先理解功能,再用目标语言自然地描述它——不是翻译描述功能的文字**(用户原则)。流程:读代码/看界面,弄清"这个功能到底做了什么、用户在什么场景下用它、为什么需要",丢开英文原句,再用该语言母语者会说的方式讲出来。SEO 同样不是翻译,而是对该市场的分析(第 4 节)。遇到新功能,先把"功能是什么"记进第 13 节功能地图。
- **你是在重新表述、意译、创译**:要做的是把这个功能/选项**告诉**该语言的用户它是做什么的,不是照搬英语。**先读代码理解功能**,再写。
- **不因英语简短而缩减**:英语里要绕很多话才能说清的功能,在另一语言里可能几个词就够;反过来,英语一个词、目标语言要更多才能传达同样体验,就用更多,别删。
- **页眉按钮、页脚左下角标签**:中文/英文故意用**一个词**保持排版一致。其他语言做不到一个词时可调整,但必须考虑相邻词的**长度和词构造**,**不可一个缩写、一个全称**的突兀感(例:pl Poradniki/Projekt/Dołącz;de Anleitungen/Forum/Mitmachen/Projekt)。
- **状态徽章用短词**(pl Błąd、de Fehler)。
- **品牌名**:是否保留拉丁因受众而异(俄语读者可能不会读 Montage Subtitle Translator;挪威语保留英文反而明智)。pl/de/es 把搜索词放进品牌:`Tłumacz napisów Montage` / `Montage Untertitel-Übersetzer` / `Traductor de subtítulos Montage`。
- **"志愿者"**(英文不合适,中文有"为热情工作"的味道)、**"免费"**(有些文化是最贵的暗示,南亚/非洲却是极好的招牌)、**数字**(稳定性等,看受众在不在意)、**愿景**(目标群体吃这套才写)、**路线图完全不提**。
- **署名 cue**(`credit.text`,出现在成片里):短、自然、免变格;按**目标语言**取用;`{brand}` 由构建时该语言 `app.brand` 替换。
- **页脚口号 `footer.slogan`**("Powered by Love"):es/pt/ar/tr/ko/ja/ru 直接用 `https://github.com/MontageSubs/ass-subset` 已校准译法;其他语言取情感等价(pl "Napędza nas miłość ❤️"、de "Mit Herzblut gemacht ❤️")。
- **避免同质化**:两个语言应是各自市场调查后的结果,不是同一稿的翻译(挪威语对英语理解高,过分解释不合适;另一语言就需要解释)。
- **首页三张卡片(`app.feature.1-3`)不是翻译**:每语言按当地社区习惯重写,先读 en/zh/es 的写法再创作;三卡主题固定:专业能力开放 / 超越逐行(场景上下文)/ 无账号无广告无追踪。
- **拿不准的、低置信度的、搜索结果少的内容必须深度搜索**,不要建立在错误假设上。

## 4. SEO 元数据规则与原始意图

**两条线**:SEO 元数据(`app/src/metadata/<code>.json`)是机器可读内容,我负责;可见内容用户负责。**为 SEO 改变页面可见内容的改动先否决或先问。**

**核心洞察**:用户不会去搜"开源字幕社区",那是**点击点**;吸引搜索流量的是**热词**。**热词负责被搜到,差异点负责被选中**。描述不是排名因素,影响点击率;title 才是排名信号。

**描述结构**:热词放前段(CJK 约 55 全角宽、拉丁约 110 字符内);差异点放在默认显示长度内(拉丁桌面约 155 字符)被截断也要保住;补充词放最后。宽度按像素估算,CJK 算 2,拉丁算 1。**title 预算 60 单位,description 155 单位**。同一句话要让**多个群体各自看到想看的**,不能堆词成不连贯句子。

**标题**:首页可长(`{brand} - ...`),其他页倾向极简"页面名 · 品牌";docs/tools 额外加一个搜索意图词(翻译指南/字幕工具);PWA 里首页标题只显示品牌。

**禁用/注意**:
- 不用疑问句;不写 "movie & TV";不写"高质量";不虚构评分(**不加 aggregateRating**)、不虚构不存在的功能;不写"无水印"(默认会追加署名 cue)、不写"无限制"(有每日额度)。
- fansub/typesetting 等圈内词只放 docs/discussions/about/tools,不放首页。
- **非中文页面不得出现中文/微博/哔哩哔哩**;alternateName 只放同语言名称。
- **缺失条目省略 + 构建警告**,不用英语补;models 与 docs 用词相互独立(一个用了,另一个连近义词也不用)。
- docs 描述必须含**语义准确、术语一致、人物关系正确、上下文连贯**的等价表达;不写隐私政策/服务条款。
- models:强调本地预处理、名称识别、句子识别、离线翻译引擎,**只说"涵盖",不承诺上线时间**。discussions 是讨论字幕制作与翻译的社区,不是反馈中心。history 是 noindex。
- 不对外提:状态系统、安全校验、开发管线、LLM 体系、路线图。

**差异点候选**(按当地受众取舍):不是套 API 的壳而是围绕 NMT 自研(场景识别、术语识别不译偏、句子感知、NLP、本地模型、译后质检、精心设计的字幕编辑器、本地化管理体系);**MKV 字幕轨浏览器本地提取(不上传视频、不装 MKVToolNix/ffmpeg;同行 VEED、vmeg 等多为上传视频的云端工具)**——已作为 `application.feature.12`;术语识别加速算法;上下文+术语表(免费托管工具几乎没有;"glossary"是真差异点);SDH 去除;歌词独立处理与歌词 cue 专门处理;ASS/SRT/VTT 与字幕组级 ASS 预设;双语(语言学习者);无注册/无广告/不追踪;开源 MIT;社区出品。"scene-level"是我们自己的词;"context-aware"已被大量 LLM 工具使用。

**每个新语言的调研流程**(必须做,产出画像再写文案):
1. **同行画像**:用该语言模拟 8-12 组真实搜索(翻译字幕、SRT 翻译、双语字幕、免费、免注册、开源、方向对如"英语到本语言"、痛点词);抓前 10 站的 title/description/H1/是否注册/是否水印/格式/语言数/定价;WebSearch 只给标题时用 WebFetch 取页面 meta;再用新词搜一轮;抓当地"替代方案"(桌面软件如 Subtitle Edit、字幕站、社区)。分出"搜索词"和"点击词",理解对手优势,共有的优势可展开竞争。
2. **受众/社区画像**:至少 ① 偶尔看片的普通观众 ② 重度观众/自己翻译的人 ③ 字幕分享者(想第一时间把字幕带给自己的社区/网站)④ 字幕制作者/字幕组(已有工作流,切换成本高但价值高)⑤ 开发者 ⑥ 语言学习者。每类记录:在哪活动、怎么称呼字幕、怕什么、要什么、对机翻态度。
3. **文化画像**:"免费/开源/社区/志愿者/AI"的语感;机翻污名;品牌名好不好读;**该国国民是否依赖字幕**(依赖度低的语言优先级低,如挪威);称呼体系;是否需要解释英语术语。
4. 融合成一套**该语言的 SEO 指南**,再产出内容。把指南与调研结论写进项目文档(不进仓库)。

已有发现(供参考):英文 "timestamps preserved/no sign-up/free/online/SRT/VTT/ASS" 是标配不构成差异;语言学习者搜 "dual subtitles";繁中(台湾)用"字幕檔/免註冊/線上/批次/支援/詞彙表/時間軸/隱私/本機",简转繁是台湾痛点;香港用"私隱/批量"。波兰:Napisy24 规章禁止上传"z translatora"机翻字幕,机翻在社区有污名,"translator"贬义。

**已定稿范例**(`{brand}` 占位):
- en 标题 `{brand} - Free Open-Source Online Translator`;描述 `Free AI subtitle translator, no sign-up. Translate SRT, VTT & ASS subtitles online with preserved timestamps. Privacy-friendly, open source, built by subtitlers. Glossary, scene-level context, batch and bilingual output, 200+ languages.`
- zh-Hans 标题 `{brand} - 免费开源在线字幕翻译工具`;描述 `AI驱动的免费在线字幕翻译器，无需注册，十几秒翻译SRT/VTT/ASS字幕文件，支持双语字幕，保留时间轴。开源、注重隐私，专业字幕社区出品。支持术语表，按场景翻译，上下文连贯，可批量翻译，200+语言。`
- 中文 SEO 字符串里中英文之间**不加空格**。

## 5. 每语言必做的本地化维度(逐项过一遍)

| 维度 | 要点 / 代码位置 |
|---|---|
| UI 文案 | `app/src/i18n/locales/<bcp47>.json`,键与 en 一致,**按键名字典序**;复数键 `.one/.other...` 须覆盖 `Intl.PluralRules` 全部类别;`checkI18n` 只对占位符不一致/未知标记报错,缺键仅统计覆盖率,运行时回退英文 |
| 元数据 | `app/src/metadata/<code>.json`(现 41 键,含 `application.feature.1..12`);`checkMetadata` 缺失警告、未知键/空值/占位符不一致报错。`structuredData.ts` 的 `TRANSLATOR_FEATURE_COUNT` 现为 12 |
| **模型卡片** | `app/src/model-catalog/*.json` 的 `description.<locale>`(4 个文件:3 个 NER + lexicon-subtitle),缺失回退 en。**只在 `en` 行后插入一行** |
| 语言名 | `language.name.*` 全套(约 210 个),**首字母大写**(Intl 对 es/pl 等返回小写);Intl 缺的生僻名手写;`language.name.<自身>` 同时是语言切换器的母语名 |
| **排序** | 语言菜单(右上角)与语言选择器按**该语言默认排序**(en A-Z;zh 拼音;pl ą ć ę ł 独立;sv/fi å ä ö 在 z 后;ja 五十音;ko 가나다;印度系按各自字母表)。`shellMarkup.ts` 的 `localesInMenuOrder`、`components/languageSelect.ts` 用 `Intl.Collator(界面语言)`;**必须确认该语言 ICU collator 结果合理** |
| **搜索快捷输入** | `utils/languageSearch.ts`:NFD 去重音 + 特殊字母折叠(ł đ ð ø ı ß æ œ þ);de 的 ae/oe/ue;zh 拼音/注音首字母(`languagePhonetics.ts`)。ja:罗马字/假名;ko:초성;ru/uk:拉丁转写与错误键盘布局;ar/he/fa:拉丁转写;**印度系文字:拉丁转写别名**(`utils/languageAliases.ts`:`UNIVERSAL_LANGUAGE_ALIASES` 对所有界面语言生效,如 fil ← tagalog/pilipino/tl;`ROMANIZED_ALIASES_BY_UI_LANGUAGE` 仅对该界面语言生效,bn 已建 "bangla/ingreji/hindi…",其他印度系语言按同结构扩展) |
| 推荐语言 | `utils/languageProfiles.ts` 的 `LINGUISTIC_AFFINITIES`,按界面语言给最多 8 个;注意社会/政治敏感顺序(pl:uk 在 ru 前) |
| **字体** | **每种语言用系统默认无衬线**,fallback 链支持多系统;等宽仅日志;**不要细微字体变化**。`styles/fonts.css`:根元素按语言设字体变量,**不按元素 `lang` 切换**(否则 zh-Hans 界面中的"繁體中文"会用 TC 字体);菜单项不带 `lang`,仅母语名 span 带 `lang` 且 `font-feature-settings: "locl" 0`;Han 回退链覆盖 SC/TC/HK;**避免豆腐块**;只有无法表达时(ar/he 及**印度系文字**)才切换到对应文字的系统字体,并尽量用覆盖面广的一种 |
| **单位/日期/数字** | 一律走 `Intl`(`utils/numberFormat.ts`、`localeFormat.ts`、`elapsedFormat.ts`);每语言核对:数字系统(bn 默认孟加拉数字 ০-৯ 与印度式分组,静态文案也用同一套,与运行时插值一致)、日期顺序、MB/紧凑数字单位、百分号(de `{percent} %` 带 NBSP)、秒/分/时简写 |

## 6. 技术环境与操作

- 注意:`git reset --hard` 会被自动模式拦截,不要绕过;用 `git checkout origin/main -- <file>`,差异/ZIP 一律相对 `origin/main` 计算。
- 目录:`app/`(Web App)。**本地任务不涉及 python 翻译逻辑和 worker 后端侧改动,无需同步。**
- 构建:`cd app && npm ci && npm run build`(约 2 分钟,**放后台**,`(… ; echo exit=$? >> log) &`)。`npm run build` = tsc + checkI18n + checkMetadata + checkLogicalCss + checkModelCatalog + checkRequestOrigin + vite build + prerender + emitBuildManifest + checkStatusProbeAssets。浅克隆会让 docs 步骤的 `assertFullHistory` 失败(`git fetch --depth=3000`)。新克隆没 `node_modules` 会报 `Cannot find type definition file for 'node'`。
- ZIP:`git ls-files -m -o --exclude-standard | zip -q out.zip -@`;删除清单用 `git diff --name-only --diff-filter=DR`;**目录结构与仓库一致**。
- 新增语言改动点:`i18n/locales/<code>.json`、`metadata/<code>.json`、`model-catalog/*.json`(只在 `en` 行后加行)、`config/openGraphLocale.ts`(缺省走 `likelyTerritoryLocale`,必要时显式写)、`styles/fonts.css`、`utils/languageProfiles.ts`(**先 grep 是否已有该语言条目,避免重复键**)、`utils/languageSearch.ts` 及别名文件。语言发现、协商、hreflang、sitemap、prerender 自动。
- 前端状态:A/B 槽位缓存 + 更新 toast;`error.appOutdated` 时重试/开始/继续/重新翻译按钮禁用,界面提供"检查更新"链接复用更新 toast。
- 已知的不阻塞问题:无 JS 语言网关页按代码序排列;页面缩放被禁用(用户将修);Safari 子路径图标(无解);`GISCUS_LANGUAGES` 无 bn(giscus 不支持,回退即可)。

## 7b. 推荐语言与语言菜单架构(本轮新增)

**目标语言推荐(`utils/languageProfiles.ts`)**:目的=用户可能同时理解的第二语言;同国/同族语言优先。**英语不一定排第二**:按该国英语普及度放位置——英语能力高(北欧、荷兰、波兰、菲律宾、南非/尼日利亚/肯尼亚、印度/孟加拉等把英语当教育语言的地区)放 2-3 位;中等(法/意/西/葡/希/巴尔干/土/阿)放 4-5 位;偏低(日/韩/中、泰/越/缅/柬/老、俄/中亚、波斯)放 5 位之后。理由:懂英语的人通常直接用英语界面,所以英语只是"可能想翻成的目标"而非默认第二语言。**中文相关表(zh/zh-hans/zh-hant/ja/ko)保持用户原始顺序,不得改动。** UI 只显示前 5 个,前 5 位最重要。算法 `quickPickLanguageCodes(uiLocale, navigatorLanguages)`:界面语言 → 浏览器声明的非英语语言 → 地区附加(`REGION_AFFINITIES`:PH、ES、HK、CH、BE、ZA、NG、KE/TZ、PE/BO/EC/PY、PK、BD、LK、NP、SG)→ 各声明语言的亲缘表(英语通用表不参与,留给兜底;`en-in` 有专表;印度语系自动并入 hi 表)→ 英语表兜底;最多 8 个。新增语言只需加一条亲缘表。菲律宾:fil/ceb/ilo/hil/bik/pam/pag 互推,fil 第二位固定 ceb。he 沿用用户的 `he,en,ru,ar,fr,es` 并补 am/yi。

**界面语言菜单(右上角)**:`<input type=checkbox#locale-toggle>` + 全屏 `<label>` 遮罩(无 JS 也能展开/关闭,与汉堡菜单 `#nav-toggle` + `label.nav-scrim` 同构);弹层结构=搜索框(`data-requires-js`,无 JS 隐藏)/语言列表(独立滚动,桌面最多 9 行,行高 `--locale-row-height`,矮屏自动收缩)/"帮助翻译"(固定底部)。手机(`--mobile`)为右侧抽屉,搜索框在最上。排序:浏览器 `navigator.languages` 匹配到的界面语言置顶(仅客户端渲染;预渲染/无 JS 用固定语言序),其后为原排序,中间 `role=separator`。搜索=显示名(界面语言)+原文名,忽略重音,另并入 `matchesLanguageQuery`(代码/英文名/别名/拼音)。触屏或紧凑布局打开时不聚焦输入框(避免弹键盘),焦点落在弹层;桌面聚焦搜索框;Esc 关闭并还焦点;↑↓/Home/End 在选项间移动;`role=status` 播报结果数(键 `nav.languageShown` 用 `{total}`,避免复数)。新增 i18n 键:`nav.languageNone/Search/Shown`(9 个语言已补)。

**术语表编辑器(`components/glossaryEditor.ts` + `glossaryMarkup.ts`)**:工具栏(说明+Rows/Bulk 分段按钮)只渲染一次、原地更新(`syncGlossaryToolbar`),正文在 `.glossary__body`(`display:contents`)里重绘——这样按钮不会被销毁重建后再 `focus()` 出现焦点环(曾表现为"按下的那个更大")。行区 `min-height:6rem` 只在 ≥3 行时生效,避免只剩 1-2 行时页脚按钮被撑到第三行。`musicTopAlign.desc` 已按用户 RTL 改动(右上角用于 he/ar/fa 目标)同步到全部语言。he 已由用户完成并合入。
